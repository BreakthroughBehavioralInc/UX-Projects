# Sierra — CSA Handoff Panel MVP

**Project:** KR-2-2 Reduce AHT &nbsp;·&nbsp; **Script templates:** Pending SME sign-off (Taylor / Farra)

---

## What this is

When Sierra (the IVR AI) transfers a call to a live CSA advocate, it sends a structured
payload describing what it learned about the caller. The **Handoff Panel** surfaces that
payload as a single actionable card in a right-rail sidebar — so the advocate has full
context the moment the call connects.

This Storybook contains **only the final designs** for developer handoff:

│                                  │  [Clear]         │

- **Right rail width:** 400 px (fixed)
- **Rail appears:** animated slide-in ~400 ms after payload arrives
- **Rail hides:** slide-out on "Clear" (call ended)
- **Main content placeholder:** shows `"Patient Search"` or `"Patient Profile"` depending on auth state.
  The real implementation replaces this with the existing CSA Patient Search / Patient Profile pages.

## Implementation requirements

### 1. Trigger & Data Contract *(informational — dev requirement)*

- Panel is populated by Sierra's handoff payload at call transfer time
- All display strings (summary, script) arrive pre-populated — the panel renders, never derives
- Payload schema and delivery SLA to be defined by Engineering / Sierra team

### 2. Caller Identity

- Display patient name when matched; collected fields when partially captured; "Unknown caller" when neither
- Caregiver proxy: patient shown is the dependent — summary must make clear the caller is the parent/guardian, not the patient
- Always show: TFN, Call ID

### 3. Authentication Status

- Two states only: **Authenticated** · **Not authenticated**
- Spanish-speaking callers are classified as Not authenticated (language-routed, no IVR auth)
- Spanish context is conveyed through the handoff card content, not a separate chip

### 4. Consent Status

- Three states: **Accepted** · **Declined** · **Not Read**
- Not Read covers cases where Sierra did not present consent (pharmacy, Spanish-routed, retention callers)

### 5. Handoff Card — Visual Severity

- **Emergency:** emergency urgency signal or mental health crisis intent
- **Error:** Consent Declined + scheduling intent (booking is blocked)
- **Warning:** Not authenticated, or Consent Declined + non-scheduling intent
- **Neutral:** Authenticated + Consent Accepted, or consent Not Read on a non-blocking caller type
- Worst state between auth and consent wins

### 6. Handoff Card — Summary

- 1–2 sentences describing why the caller is calling, in plain language
- Generated and populated by Sierra before handoff — rendered as-is, read-only, not editable by the agent for MVP
- Should include: intent, chief complaint or key context, service line if confident
- Fallback when Sierra cannot generate: generic label from intent type

### 7. Suggested Script & Templates

- First line the agent reads aloud when they pick up
- Sierra selects the template and populates variables — deterministic, not LLM-generated per call
- Variables drawn from payload: `{firstName}`, `{patientName}`, `{chiefComplaint}`, `{serviceLine}`, etc.
- Template library proposed by this team (WIP), refined and approved with Taylor and Farra
- One template per scenario type — caller type, intent, auth state, consent state, and service line all influence template selection:
  - **Behavioral health:** warm, non-clinical tone — distinct from standard booking script
  - **Consent declined + scheduling:** acknowledges the block, does not offer to book
  - **Billing inquiry:** references the billing question specifically
  - **Caregiver proxy:** addresses the parent, references child by name
  - **Spanish-speaking:** script delivered in Spanish
  - **Retention / caller requested live agent:** acknowledges they wanted a person, not the IVR
  - **Emergency / crisis:** immediate, grounding language
- If Sierra sends no script: script block is omitted — no fallback fabrication
- Clearly labeled "Suggested script" so the agent knows it is AI-assisted

### 8. Caller Types

- **Member — standard flow**
- **Member — prescription / refill:** member calling for their own medication refill; no caregiver involvement; script references the medication or refill request if captured in the payload
- **Member — prescription inquiry:** member with general questions about prescriptions, coverage, or pharmacy access; non-booking intent; consent Not Read
- **Caregiver proxy:** parent/guardian calling for a minor; script addresses the parent, patient shown is the child
- **Pharmacy / provider:** calling on behalf of a patient; consent Not Read; script references patient by name
- **Spanish-speaking:** language-routed, no auth or consent captured; script in Spanish
- **Unknown / live agent request:** no identity, no auth; agent asked to speak to a person

### 9. Intent Types

- **Schedule care** — primary care, urgent care, behavioral health, wellness
- **Billing inquiry** — non-scheduling; Consent Declined is non-blocking
- **Dermatology inquiry** — informational, not a booking request
- **Prescription / refill** — non-scheduling; member calling for their own medication
- **Caller requested live agent** — bypassed or exited the IVR to reach a person; no visit reason, no auth collected
- **Emergency / mental health crisis** — overrides all other states; Crisis Protocol always visible

### 10. Agent Landing State

Defines where the agent is navigated in the CSA platform based on handoff context — the panel informs this but does not control it:

- **Authenticated** → lands on Patient Profile
- **Not authenticated** → lands on Patient Search with IVR-collected fields pre-populated and search already run; agent selects the correct match manually
- **Multi-account** → lands on Patient Search; agent selects the correct affiliation manually
- Existing platform operations (intake, consent process, crisis protocol) are not in scope — the panel informs status only

### 11. Panel Dismissal & Persistence

- Right rail only
- Can be collapsed and reopened by the agent at any time
- Persistent across navigation — available regardless of where the agent is in the CSA platform during an active call
- Clear button removes the patient context from the panel and navigates the agent to the default home state — it does not end the call

### 12. Empty / Dropped Call State

- Panel starts empty when the call dropped before Sierra completed handoff
- Agent enters a Call ID manually to restore the session
- Restored session displays the same panel as a normal handoff

### 13. Helpfulness Rating

- "Was this helpful?" thumbs up / thumbs down control appears below the handoff card once a payload is loaded
- **Thumbs up:** closes the rating UI and shows a brief "Thanks for your feedback!" confirmation
- **Thumbs down:** reveals an optional free-text field ("What could go better?") with a Submit button
- Rating resets when the panel is cleared (new call / new interaction ID)
- Rating and feedback are submitted per interaction, keyed to the interaction ID
- **⚠️ Backend endpoint not yet defined — requires engineering ticket (Camille)**

## What the main content placeholder represents

The `[Patient Search]` / `[Patient Profile]` text in these stories is a single placeholder
line. In production:

- **Patient Search** → the existing Patient Search page (unauthenticated or no payload state)
- **Patient Profile** → the existing Patient Profile page (authenticated member confirmed)

The handoff panel is independent of the main content; it should mount and work without
changes to the existing Patient Search / Profile pages.
